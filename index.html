מה זה PLC?

בקר לוגי מתוכנת (Programmable Logic Controller) — מחשב תעשייתי קשיח שמותקן בארון חשמל על מסילת DIN (DIN Rail).

  • מקבל מתח תעשייתי של 24V DC (ולעתים 230V AC) ישירות מחיישנים ומלחצנים.
  • מודולרי: מוסיפים כרטיסי כניסות/יציאות (I/O Modules) לפי הצורך.
  • מתוכנת בשפות תעשייתיות לפי תקן IEC 61131-3, בעיקר שפת סולם (Ladder Diagram) — שנראית כמו שרטוט חשמלי של מגעים וסלילים.
  • רץ במחזור סריקה קבוע (Scan Cycle): קורא כניסות ← מריץ תוכנית ← כותב יציאות, שוב ושוב.
  • יצרנים מוכרים: Siemens, Allen-Bradley, Schneider, Unitronics (חברה ישראלית!).

מה זה מיקרו-בקר?

מיקרו-בקר (Microcontroller, MCU) — שבב אחד קטן שמכיל מעבד, זיכרון וכניסות/יציאות. מחשב שלם בגודל של ציפורן.

  • עובד במתח נמוך של 3.3V או 5V. חיבור ישיר של 24V או 230V ישרוף אותו — צריך ממסר או מצמד אופטי (Optocoupler) באמצע.
  • מתוכנת בשפות תכנות כמו C/C++ או MicroPython.
  • Arduino — לוח פיתוח פשוט ללימוד ולאב-טיפוס (Prototype).
  • ESP32 — מיקרו-בקר מהיר יותר עם Wi-Fi ו-Bluetooth מובנים, פופולרי במוצרי בית חכם ואינטרנט של הדברים (IoT).

המשימה: כשלוחצים על לחצן — נורה נדלקת.

ב-Arduino (שפת C++): 
void loop() {
  if (digitalRead(2) == HIGH) {  // is the button pressed?
    digitalWrite(13, HIGH);      // turn the light on
  } else {
    digitalWrite(13, LOW);       // turn the light off

}

5שילוב בינה מלאכותית (AI) בעבודה עם בקרים 20 דקות

כלי AI הם עוזר מקצועי מצוין — אבל המהנדס אחראי על התוצאה. מסר מרכזי לתלמידים: ה-AI הוא כמו טכנאי מתחיל מהיר ומוכשר, שמדי פעם טועה בביטחון מלא.

באילו שלבים משתמשים ב-AI?

שלב בפרויקטמה ה-AI עושהדוגמה לבקשה (Prompt)מה המהנדס חייב לבדוק
1. תכנון מערכת
System Design		מציע ארכיטקטורה, רכיבים ובחירת בקר"אני רוצה לבנות מערכת השקיה לגינה. איזה בקר ואילו חיישנים כדאי?"האם הרכיבים קיימים ומתאימים למתח ולתקציב
2. תכנון חשמלימסביר חיבורים, מחשב נגדים וזרמים"כמה נגד צריך לנורית LED אדומה ביציאה של 5V?"חישוב חוק אוהם בעצמכם — טעות כאן שורפת רכיבים
3. כתיבת קוד
Coding		כותב קוד Arduino/ESP32, מסביר אותו שורה אחר שורה, עוזר לתרגם לוגיקה לשפת טקסט מובנה (Structured Text) של PLC"כתוב קוד ESP32 שמדליק מאוורר כשהטמפרטורה מעל 28 מעלות, והסבר כל שורה"שמספרי הפינים (Pins) תואמים לחיווט האמיתי; להבין כל שורה לפני העלאה
4. איתור תקלות
Debugging		מפענח הודעות שגיאה, מציע סיבות אפשריות לתקלה לפי התסמינים"המנוע לא מסתובב למרות שהקוד עולה. הנה הקוד ותיאור החיבור. מה לבדוק?"לאמת במדידה אמיתית עם מולטימטר — ה-AI לא רואה את המעגל
5. תיעוד ותחזוקהכותב הערות לקוד, מסמכי הפעלה, מפרש קבצי לוג של תקלות"סכם את רשימת ההתראות (Alarms) מהשבוע האחרון ומצא תבנית חוזרת"שהמסקנות תואמות את הנתונים
בתעשייה משתמשים גם ב-AI שרץ בתוך המערכתתחזוקה חזויה (Predictive Maintenance) — חיישני רטט וחום על מנוע שולחים נתונים, ומודל AI מזהה שהמנוע עומד להתקלקל לפני שזה קורה. יש אפילו מודלים קטנים שרצים על מיקרו-בקר עצמו (TinyML), למשל זיהוי קולי של "הדלק" על ESP32.

הדגמה חיה בכיתה (10 דקות)

  1. הקרינו על המסך כלי AI (כמו Claude או ChatGPT) ובקשו: "כתוב קוד Arduino שמהבהב נורה כל שנייה, והסבר לתלמיד כיתה י' כל שורה."
  2. קראו יחד עם הכיתה את ההסבר. אם יש לוח Arduino — העלו את הקוד וראו שהוא עובד.
  3. שתלו תקלה: מחקו נקודה-פסיק אחת בקוד, הדביקו את הודעת השגיאה לכלי ושאלו מה הבעיה. כך התלמידים רואים Debugging בעזרת AI.
  4. שאלו את הכלי שאלה שעלולה להוביל לטעות, כמו מספר פין של לוח ספציפי — ובדקו מול דף הנתונים (Datasheet). המסר: תמיד מאמתים.

כללי זהב לעבודה עם AI (לכתוב על הלוח)

  • מבינים לפני שמעתיקים — קוד שלא הבנתם לא עולה לבקר.
  • בטיחות קודמת לכל — במעגלי 230V ובמערכות PLC שמפעילות מכונות, כל שינוי עובר בדיקה של אדם מוסמך.
  • נותנים הקשר — ככל שתפרטו יותר (דגם הלוח, החיבורים, הודעת השגיאה) — התשובה תהיה טובה יותר.
  • מאמתים מול המקור — דף נתונים, מדריך יצרן, מדידה במולטימטר.
